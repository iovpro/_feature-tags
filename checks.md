# Проверка целостности и QA scope

Приложение к [spec.md](spec.md). Описывает проверки целостности тегов и формирование
QA scope по изменениям. Автоматизировано в инструменте `ftags` ([tool/README.md](tool/README.md));
grep-рецепты ниже — fallback без инструмента.

## Классы находок

Полный перечень проверок. Классы `format` … `field` сканер находит по коду, `orphan` … `registry` —
сверкой кода с реестром, `deprecated` — только в режиме `check --base <rev>`. Номера в последней колонке —
grep-рецепты из §Проверка целостности; «инструмент» — grep-эквивалента нет.

| Класс        | Что находит                                                                                                                                                  | Правило spec.md                          | Grep       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- | ---------- |
| `format`     | Тег вне грамматики: недопустимые символы, неизвестный маркер, голый доменный тег; тег фичи на функции или тег флоу на типе; маркер на теге фичи или на тесте | §Формат, §Маркеры (п. 5), §Куда и как ставить | № 2 частично |
| `text`       | Тег-строка не из одних тегов: текст до или после тега, лишние пробелы, `#f:` без маркера комментария                                                         | §Куда и как ставить, «Запрещено»         | № 2        |
| `placement`  | Тег-группа не связана с объявлением: вторая пустая строка, следующая тег-строка, конец файла или строка кода, не являющаяся объявлением                       | §Куда и как ставить (цепочка связи)      | инструмент |
| `file`       | Тег в шапке файла или до первого объявления                                                                                                                  | «Запрещено»: тег в шапке файла           | инструмент |
| `field`      | Тег на поле структуры, свойстве или методе интерфейса                                                                                                        | «Запрещено»: тег на поле                 | инструмент |
| `orphan`     | Тег в коде без записи в реестре (сравнение до 3 сегментов, без маркера)                                                                                     | §Формат: флоу только через реестр        | № 1        |
| `nostart`    | Флоу `partial`/`done` без `@entry`/`@operation`; исключения — `NOSTART_IGNORE`                                                                              | §Маркеры, правило 1                      | № 3        |
| `deps`       | Таблица зависимостей: неизвестный флоу, self-reference, дубликат связи                                                                                       | §Зависимости флоу                        | инструмент |
| `registry`   | Домен является префиксом другого домена                                                                                                                      | §Формат: домены не префиксы друг друга   | инструмент |
| `deprecated` | Новый тег или новая связь на `deprecated`-флоу относительно `--base`                                                                                         | §Реестр, статус `deprecated`             | инструмент |

## Проверка целостности

Grep-проверки, одинаковые для всех языков. `INC` — маски файлов активных языков репозитория,
`CM` — маркеры комментариев; оба берутся из [langs/](langs/).

```bash
INC='--include=*.go'            # пример для Go-репозитория; несколько языков — несколько --include
CM='(//|#|--)'                  # маркеры однострочного комментария активных языков
REG=features.md                 # реестр в корне репозитория (конвенция)

# 1. Сироты: теги в коде, отсутствующие в реестре. Маркер отбрасывается, тег усекается до 3 сегментов.
grep -rhoE '#f:[a-z0-9.]+' $INC . \
  | sed -E 's/^(#f:[^.]+(\.[^.]+){0,2}).*/\1/' | sort -u > /tmp/in-code
cat $REG \
  | grep -E '\|[[:space:]]*(planned|partial|done|deprecated)[[:space:]]*\|[[:space:]]*$' \
  | grep -oE '#f:[a-z0-9.]+' | sort -u > /tmp/in-registry
comm -23 /tmp/in-code /tmp/in-registry   # сироты в коде
comm -13 /tmp/in-code /tmp/in-registry   # флоу реестра без кода (ok для planned и для других репозиториев)

# 2. Тег-строки с посторонним текстом
grep -rnE '#f:' $INC . \
  | grep -vE "$CM (#f:[a-z0-9]+(\.[a-z0-9]+)*(@(entry|operation|recv))?)( #f:[a-z0-9]+(\.[a-z0-9]+)*(@(entry|operation|recv))?)*[[:space:]]*$"

# 3. Реализованные флоу без стартовой точки. Проверка выполняется сразу по всем репозиториям проекта.
for f in $(cat $REG \
  | grep -E '\|[[:space:]]*(partial|done)[[:space:]]*\|[[:space:]]*$' \
  | grep -oE '#f:[a-z0-9]+\.[a-z0-9]+\.[a-z0-9]+' | sort -u); do
  grep -rqE "${f}(\.[a-z0-9]+)*@(entry|operation)([[:space:]]|$)" $INC . \
    || echo "NO START: $f"
done
```

Тесты флоу для точечного регресса ищутся по конвенции языка — рецепты в [langs/](langs/).
Классы `placement`, `file`, `field`, `deps`, `registry`, `deprecated` grep не отличает от валидной разметки —
их находит только `ftags check`.

## QA scope по изменениям

QA scope — перечень затронутых флоу для перепроверки. Источники: теги изменённых объявлений,
изменения реестра, обратное транзитивное замыкание зависимостей
(§Зависимости в [spec.md](spec.md#зависимости-флоу)).

Base задаётся явно (`--base <rev>`); head — рабочее дерево (staged + unstaged + untracked) либо
`--head <rev>`. Анализ читает обе стороны diff для учёта удалённых/переименованных объявлений
и снятых тегов.

### Категории

| Категория    | Что значит для QA                                                          |
| ------------ | -------------------------------------------------------------------------- |
| `new`        | Новый флоу — проверить впервые                                             |
| `changed`    | Production-код флоу изменён — проверить на регресс                         |
| `affected`   | Флоу не менялся, но изменилась операция, от которой он зависит (по реестру) |
| `deprecated` | Флоу выведен из использования — проверить, что замена работает             |

Приоритет: `deprecated → new → changed → affected`. Один флоу — одна категория.

### Правила

1. **Изменение реестра** (описание, спека, статус, dependency edge) = прямое изменение флоу (`changed`),
   даже без production-кода в diff.
2. **Тег уровня фичи:** изменение типа консервативно затрагивает все реализованные дочерние флоу +
   граф зависимостей.
3. **Affected:** для каждого флоу показывается цепочка зависимости до изменённой операции.

Выход: отчёт `ftags qa-scope --base <rev>`; переносится в документ задачи, принятый в проекте.
