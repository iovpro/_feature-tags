# Фич-хэштеги: привязки к языкам

Приложение к [spec.md](spec.md). Ядро описывает правила в терминах «объявление»,
«тег-строка», «тег-группа», «ветка», «тест»; здесь — как эти термины ложатся на конкретный язык или формат.
Статус `active` — профиль проверен и протестирован; `reference` — заготовка,
активируется при внедрении в репозиторий.

Каждому разделу соответствует машинный профиль `tool/langs/<язык>.conf` для `ftags` — те же поля в виде
shell-переменных. Меняются вместе.

Каждый раздел задаёт одно и то же:

| Поле             | Что задаёт                                                                  |
| ---------------- | --------------------------------------------------------------------------- |
| Файлы            | Маски для `INC` в проверках целостности ([checks.md](checks.md)); исключения                          |
| Комментарий      | Маркер однострочного комментария для `CM`                                    |
| Тег-группа       | Как отдельная comment group связывается с последующим объявлением             |
| Объявления       | Что считается объявлением в этом языке                                       |
| Ветка            | Как ставится инлайн-тег                                                      |
| Тесты            | Маска тест-файлов, как распознать тест и связать с ним тег-группу           |
| Точечный прогон  | Имена тестов флоу → запуск только их                                          |

## Соответствие полей раздела и переменных профиля

| Поле раздела     | Переменная `*.conf` | Примечание                                                     |
| ---------------- | ------------------- | -------------------------------------------------------------- |
| (имя)            | `NAME`              | Имя профиля = имя файла без `.conf`                            |
| Файлы            | `FILES`             | Маски через пробел; матч по basename (без `/`) или пути (с `/`) |
| Файлы (искл.)    | `EXCLUDE`           | Маски исключений, та же семантика                               |
| Комментарий      | `COMMENT`           | Маркер однострочного комментария (`//`, `#`, `--`)              |
| Тег-группа       | `GAP_RE`            | ERE строк между пустой строкой после тег-группы и объявлением   |
| (сканер)         | `SCANNER`           | Имя внешнего сканера (пустое → `scan.awk`); напр. `scan-ts.mjs` |
| Объявления       | `DECL_RE`           | ERE строки объявления                                           |
| (доп. цели тега) | `TAG_TARGET_RE`     | ERE строк, где тег-группа допустима помимо `DECL_RE`            |
| (имя объявления) | `DECL_NAME_STRIP`   | ERE префикса; далее обрезка по `[ (\[{:=]`                     |
| Куда ставить     | `FLOW_DECL_RE`      | Объявления, требующие тег ≥ 3 сегментов                         |
| Куда ставить     | `FEAT_DECL_RE`      | Объявления, требующие ровно 2 сегмента                          |
| Ветка            | `BRANCH_RE`         | Текст до маркера, где допустим хвостовой тег                    |
| (поля)           | `FIELD_OPEN_RE`     | Начало контекста struct/interface                                |
| (поля)           | `FIELD_CLOSE_RE`    | Конец контекста struct/interface                                 |
| (шапка)          | `HEADER_RE`         | Строка, означающая шапку файла                                  |
| Тесты (файлы)    | `TEST_FILES`        | Маски тест-файлов                                               |
| Тесты (regex)    | `TEST_RE`           | ERE строки-теста                                                |
| Тесты (имя)      | `TEST_NAME_STRIP`   | ERE префикса имени теста                                        |
| Тесты (имя)      | `TEST_NAME_END`     | ERE хвоста имени теста                                          |
| Точечный прогон  | `RUN_CMD`           | Шаблон; `{TESTS}` → склейка имён                               |
| Точечный прогон  | `RUN_JOIN`          | Разделитель склейки                                             |
| (стенд)          | `EVIDENCE_CMD`      | Доказательство для профиля без тестов (текст команды стенда)    |

Формат профиля — декларативный `KEY=VALUE` (одна пара на строку, `#` — комментарий); инструмент
разбирает его как данные, без `source`/`eval`. Кавычки вокруг значения (одинарные или двойные) снимаются.

## Чеклист: добавить язык

1. Раздел по таблице выше: все семь полей заполнены, статус указан.
2. Тег-группа отделена пустой строкой от doc-comment/docstring, декораторов, атрибутов и объявления;
   профиль умеет связать её с ближайшим следующим объявлением без включения в генерируемую документацию.
3. Regex распознавания теста и команда точечного прогона проверены на реальном тест-файле.
4. Создан профиль `tool/langs/<язык>.conf` с теми же полями; язык добавлен в `.ftags.conf` репозитория.
5. Пример кода в разделе — минимальный и валидный.
6. Сводная таблица в начале файла обновлена.
