# Инструмент ftags

Shell-инструмент без сборки, живёт в `tool/` и переносится вместе с репозиторием.
Ядро — bash, POSIX awk, grep, sed, git. Разбор по профилям языков: для go/sh/yaml — построчный
regex-сканер (scan.awk); для ts — AST-сканер на TypeScript compiler API (scan-ts.mjs, требует Node.js).
Профиль выбирает сканер через ключ `SCANNER` в `.conf` (следствия — в §Границы).

Ядро правил — [spec.md](../spec.md); развёртывание — [bootstrap.md](../bootstrap.md).

## Структура

```
tool/
├── ftags.sh             # единая точка входа, подкоманды ниже
├── scan.awk             # POSIX awk сканер: один проход по файлам профиля → поток записей D/V/E
├── scan-ts.mjs          # AST-сканер для TS/JS на TypeScript compiler API → тот же D/V/E формат
├── langs/
│   ├── go.conf          # профиль языка: маски файлов, маркер комментария,
│   ├── yaml.conf        # регулярки объявления и теста, шаблон точечного прогона
│   ├── sh.conf
│   └── ts.conf          # TS/JS профиль: SCANNER=scan-ts.mjs, regex-ключи пустые
└── tests/
    ├── ftags.bats       # bats-core тесты
    ├── xplat.sh         # кросс-платформенный прогон: BSD awk, gawk, mawk (debian), busybox (alpine)
    └── fixtures/        # clean/ — Go/sh/yaml; violations/ — по классу нарушений; lang-ts/ — TS/JS
```

Профили `langs/*.conf` — машинный источник; [langs/](../langs/) описывает их для человека, оба
обновляются вместе. Конфиг репозитория — `.ftags.conf` в его корне: декларативный `KEY=VALUE` с фиксированным
набором ключей; инструмент разбирает его как данные и никогда не выполняет через `source`/`.`/`eval`.
Реестр по конвенции — `features.md` в корне репозитория. Состав ключей, шаблон реестра и Makefile-обёртка
(`make ftags-check`, одинаковые команды во всех репозиториях) — [bootstrap.md](../bootstrap.md).

## Команды

| Команда                                | Что делает                                                                            |
| -------------------------------------- | ------------------------------------------------------------------------------------- |
| `trace <флоу>`                         | Объявления флоу по файлам: `@entry`, `@operation`, затем продолжения; `@recv` выделен |
| `entries [<флоу>]`                     | Только внешние старты `@entry`                                                        |
| `operations [<флоу>]`                  | Только старты переиспользуемых/внутренних операций `@operation`                       |
| `check [--base <rev>]`                 | Статическая целостность; с `--base` также запрещает новые теги/edges на `deprecated`  |
| `tests <флоу>`                         | Имена тестов флоу и готовая команда точечного прогона из профиля языка                |
| `changed --base <rev> [--head <rev>]`  | Прямо/косвенно затронутые флоу и объявления без тега                                  |
| `qa-scope --base <rev> [--head <rev>]` | Markdown для QA: те же категории с цепочками, спеками, стартовыми точками и тестами   |
| `scan`                                 | Отладочный дамп записей сканера (TSV)                                                 |

Дополнительные опции: `-C <dir>` — сменить каталог до поиска `.ftags.conf`;
`--lang <name>` — ограничить одним профилем; `--reg-base <rev>` — ревизия реестра (когда реестр
в другом git-репозитории).
Коды выхода: `0` — успех; `1` — нарушения/untagged/not found; `2` — ошибка конфигурации/окружения.

Умолчание `--reg-base`: если реестр в том же git-репозитории, что и код, базой реестра служит `--base`;
если в другом — `HEAD` репозитория реестра, head — его рабочее дерево. При явном `--head <rev>`
`--reg-base` задаётся явно. stderr печатает `# registry base: <file>@<rev>`.

Ограничения: ядро — POSIX-подмножество утилит (bash 3.2+, POSIX awk); проверяется на macOS (BSD),
Debian (mawk, gawk) и Alpine (busybox awk, gawk). AST-сканер TS/JS требует Node.js и пакет `typescript`
(резолвится из `node_modules` проекта или из директории сканера). Windows — только через WSL.
Grep-проверки из [checks.md](../checks.md) остаются как fallback без инструмента.

Makefile репозитория: `make ftags-check`, `make ftags-changed`, `make ftags-qa-scope`.
Настройка — [bootstrap.md](../bootstrap.md).

## Границы

Инструмент проецирует diff на теги и реестр; чего нет в тегах и реестре, для него не существует.
Границы одинаковы для любого языка и репозитория:

| Граница               | Следствие                                                                                                                                                                                                     | Кто закрывает                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Разбор без AST (go/sh/yaml) | Любая правка кода в диапазоне объявления считается изменением флоу: переименование, сигнатура и логика неразличимы. Однострочные строки `GAP_RE` фильтруются автоматически, блочные — нет. TS/JS использует AST-сканер: class members, namespace members, вложенные переменные распознаются корректно | Исполнитель различает по diff                             |
| Замыкание по таблице  | Косвенное влияние считается только по таблице зависимостей реестра; вызовы в коде не анализируются, ребро вне таблицы не существует. Пустая категория `affected` означает «нет по таблице», а не «нет в коде» | Автор флоу — ребро в таблице при каждом новом потребителе |
| Состав, не порядок    | `trace` группирует объявления по маркерам и файлам; последовательность вызовов не восстанавливается                                                                                                           | Реестр — порядок шагов в описании флоу                    |
| Только помеченный код | Объявление без тега видно лишь в `untagged` при его изменении; флоу без тегов не находится ни `trace`, ни `changed`. Полнота результата равна полноте разметки                                                | Разработчик — тег на каждом объявлении флоу               |
| Расширение тега фичи  | Изменение объявления с тегом уровня фичи консервативно затрагивает все реализованные флоу этой фичи; инструмент добавляет подсказку `(через #f:<фича>)`                                                       | Исполнитель различает по diff                             |
